01 Project Overview

产品概述

ECHO 是一套由 Smart Ring、ECHO App 与 Haptic Device 组成的女本位身体感知互动系统。身体变化是互动线索，不是替用户判断感受或意愿。

Core question

记录身体数据，不等于认识身体。

现有可穿戴擅长数值展示。ECHO 关心的是：当身体信号进入互动，它能否帮助用户更细致地察觉当下，并在安全边界内留下自己的长期经验。

Slogan

把 YES, I DO 说给自己

婚礼上，人们戴上戒指对另一个人说 Yes, I do。这一次，我们想请你把这句话留给自己。

  • 我愿意正视自己的欲望。
  • 我愿意开始了解自己的身体。
  • 我愿意承认自己的喜欢、不喜欢，以及它们随时可能发生的变化。
  • 我愿意把关于身体的最终选择权，留在自己手里。

02 Research & Insights

研究与洞察

问卷呈现需求与顾虑，文献解释信号与体验的差异，三次深访检查硬件和交互假设。

84.8%认为身体认知重要
59.5%认为自己比较／非常了解
46.8%希望低打扰回应
51.9%担心操作或提示打断体验

01 / Finding

信号可以测量，感受不能被代言

身体反应与主观体验并不总是一一对应。感知，但不定义。

02 / Finding

需要的不只是更多数据

把身体信号、主动反馈与主观记录连接起来，才形成个人身体经验。

03 / Finding

技术要出现，但不能抢走注意力

降低注意力成本，而不是增加操作。

03 Product Experience

一个系统，三个触点

从感知身体变化，到形成回应，ECHO 将一次体验连接成完整互动闭环。

01 · Sense

智能戒指

感知体验过程中的心率和血氧变化，并保留全系统暂停入口。

02 · Adapt

ECHO App

接收身体信号，通过 AI 互动、主动询问与用户选择，持续调整体验内容。

03 · Respond

触觉反馈设备

提供压力与实体按键输入，并接收经安全策略确认后的振动反馈。

SENSE → ADAPT → RESPOND

One experience

一次完整体验

  1. 选择体验

    选择当下想进入的叙事与互动方式。

  2. 设定边界

    开始之前，确认自己的体验范围与边界。

  3. 建立基线

    读取此刻的心率与血氧，为观察相对变化建立参照。

  4. 互动与记录

    体验中作出选择；结束后，用户决定是否保存本次身体变化与主观感受。

04 Technology

从信号到回应

ECHO 不让 AI 直接控制硬件。信号进入 App，经过状态判断、AI 互动与本地安全策略，才形成可执行的回应。

  1. 01SenseSmart Ring 心率／血氧 · Haptic 压力／按键 · BLE
  2. 02InterpretAndroid App · State Engine（状态 + 置信度）
  3. 03DecideAI Gateway → Content Validator → Safe Action Mapper
  4. 04ActWhitelist Action → Haptic · App 始终可 STOP／PAUSE

AI CAN SUGGEST. IT CANNOT OVERRIDE.

AI 可以提出回应，但不能越过用户和安全边界；不直接输出底层电机控制参数。

  • 设备关机键可本地关闭马达
  • 戒指长按触发全系统暂停
  • App 始终提供 STOP
  • BLE 断开进入 OFF / paused

05 Development

可运行闭环（4天）

Four days. One working loop.

  1. DAY 01

    Make it run

    环境、真机、Replay UI、传感器与马达分测。假数据可走完整管线。

  2. DAY 02

    Make it connect

    双 BLE、Packet Codec、暂停链路。两设备可独立收发，STOP 可关闭动作。

  3. DAY 03

    Make it respond

    State Engine、结构化 AI、TTS、安全动作映射。一条真实端到端剧情连续运行。

  4. DAY 04

    Make it survive

    异常处理、Replay 兜底、装配与彩排。完整演示，异常时可切换 Replay。
